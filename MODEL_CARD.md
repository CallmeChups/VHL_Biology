# VHL Biology — Model Card

## Scope

The current client package is a Windows/Conda LAN release. The backend
pipeline actively loads the CatBoost classifier and the phase-detector models.
The package also carries LSTM checkpoints used by
`process_and_predict_lstm` and a historical random-forest artifact. Those
artifacts are not called by the current FastAPI session pipeline unless a
caller explicitly invokes the corresponding utility; the historical
random-forest file has no current backend endpoint reference.

All paths below are repository-relative and are resolved from the release
directory. The authoritative packaged list and SHA-256 values are in
`RELEASE_MANIFEST.json`, generated by `scripts\build_release.ps1`.

## Supported input and output boundaries

The supported client flow is UTF-16 instrument TXT → adaptive peak extraction
→ CatBoost classification → phase tags → toxicity. Phase tags can be
`phase1`, `transition`, or `phase2`; transition rows are excluded from the
toxicity calculation. BOD calibration is a separate endpoint and uses two
client-supplied calibration points.

The README's historical representative result is an approved reference, not a
guarantee for every machine or sample. The current release manifest is the
source of truth for the observed release smoke result and acceptance status.

## Integrity and checksum procedure

The release builder computes SHA-256 for every path in `runtime_models`:

```powershell
Get-FileHash .\model\catboost_model.cbm -Algorithm SHA256
Get-FileHash .\model\phase_detector_metal.pkl -Algorithm SHA256
Get-Content .\RELEASE_MANIFEST.json
```

Compare each packaged file with the matching `checksums` entry before
starting a client release. If a checksum differs, restore the model from the
same release or a verified backup; do not mix model files across releases.
